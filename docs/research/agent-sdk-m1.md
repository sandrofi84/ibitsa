## Summary

The SDK has every §11.4 feature that M1 needs. Nothing is missing. Four things differ from what §11.4 and §11.3 assume:

1. **There is no `compact()` method.** To compact, you send `/compact` as a user message. You watch it with the `compact_boundary` message and the `status: 'compacting'` message.
2. **Questions arrive through the same `canUseTool` callback as permissions.** They come as a call to the tool `AskUserQuestion`. To answer, you return `updatedInput: { questions, answers }`. The §11.3 sketch has no way to answer a question, so the session needs an `answerQuestion` method.
3. **`priority: 'now'` interrupts the turn** unless the message also carries `origin: { kind: 'human' }`. With that origin, background-able work keeps running. `'next'` is the default. There is also a third value, `'later'`.
4. **Cost is cumulative.** `total_cost_usd` and `modelUsage` on each turn's `result` are running totals, so you read the latest one and never sum them. `maxBudgetUsd` counts only the spend of the current `query()` call, not spend restored by `resume`.

**Mode requirement:** all of the control methods (`interrupt`, `setModel`, `getContextUsage`, `streamInput`) need **streaming input mode**, where `prompt` is an `AsyncIterable<SDKUserMessage>`. Use that mode for every session.

## Changes the §11.3 `AgentAdapter` sketch needs

1. **`AgentSession.send` priority.** Widen the type to `'now' | 'next' | 'later'`. Map Ibitsa's "send now" to `priority: 'now', origin: { kind: 'human' }`. Without that origin, `'now'` is a hard interrupt. Map "queued" to `'next'`, which is the SDK default and is read in the same turn after the current tool calls. Use `'later'` only to mean "after this turn".
2. **Add `answerQuestion(id, answers: Record<string, string | string[]>, freeText?)`.** `respondToPermission` cannot carry answers. In the Claude adapter, the `question` event and the `permission` event both come from a `canUseTool` call that is still waiting. The adapter keeps a deferred promise for each `toolUseID` and settles it from `respondToPermission` or `answerQuestion`. For a question it returns `{ behavior: 'allow', updatedInput: { questions, answers } }`. `AskUserPayload` should copy the SDK shape (`question`, `header`, `options[{label, description, preview?}]`, `multiSelect`) so the Claude adapter can pass it through unchanged.
3. **`respondToPermission` should carry the SDK's richer outcomes.** Add an optional `alwaysAllow` (which returns `updatedPermissions` from `suggestions`) and an optional `interrupt` on deny. Add `title?` and `description?` to the `permission` event: `canUseTool` provides ready-made prompt text for the "Needs you" queue.
4. **Implement `compact()` by sending `/compact`; there is no SDK method.** Keep `compact?()` and set `capabilities.compaction = true`. Add `{ type: 'resting' }`, from `status: 'compacting'`, so the rest animation starts on time. Extend `compacted` to `{ type: 'compacted'; trigger: 'manual' | 'auto'; preTokens: number; postTokens?: number }`, since auto-compaction also restores HP.
5. **`contextUsage()` source.** Use `getContextUsage({ detail: 'summary' })` while polling, so polls send no extra token-count requests, and `'full'` only when needed. Base `max` on `rawMaxTokens`, which docs describe as the context window or the lower auto-compact window. The difference between `maxTokens` and `rawMaxTokens` is not explained in the docs. Between polls, `usage` events can estimate HP from `modelUsage[*].contextWindow` and per-step input and cache tokens.
6. **Make `usage` events cumulative.** Rename the cost field to `totalCostUsd` and document it as a running total for the session, so the core does not sum it. Optionally add `byModel` (from `modelUsage`). Note that `maxBudgetUsd` covers only the current process call: after a resume, the adapter should pass `budgetUsd − alreadySpent` itself if the gold pouch should span restarts.
7. **Add end-of-turn reasons.** Split `done` into `{ type: 'turnEnd'; stopReason; terminalReason?; queuedTurns?: number }` and keep `error`. Budget exhaustion (`error_max_budget_usd`) must reach the core as its own state ("out of gold"), not as a generic error. `queued_turn_count` tells the core whether another turn follows at once.
8. **`SessionOptions.allowedTools` is ambiguous.** In the SDK, `allowedTools` **auto-approves** tools but does not restrict them. Restriction is `tools` (what is available) or `disallowedTools` (what is removed). Split the option into `tools?` (restrict, e.g. reviewer/council read-only) and `autoApprove?` (the §11.6 safe-action list). Remember to include `AskUserQuestion` when restricting. `readOnly` maps to a `tools` list (or `permissionMode: 'plan'`), not to a separate flag.
9. **Choose session ids up front.** Add `sessionId?` to `SessionOptions`, or have `startSession` return the id before the first event (the SDK `sessionId` option takes a UUID). That way §12 can save it before any work happens. `resumeSession` maps to `options.resume`. Add `listSessions(dir)` to the adapter for recovery.
10. **Use one long-lived `query()` per session in streaming input mode.** All control methods require it. `close()` maps to `Query.close()`. `interrupt()` should return the `still_queued` receipt. Messages listed there will still run after the stop. The control protocol has a `cancel_queued` flag that would cancel them, but the public `Query.interrupt()` takes no arguments, so the SDK does not expose it. To make "stop" mean "stop everything", the adapter must avoid sending messages ahead of time: it should hold them itself, or send them with `'later'`.
11. **Capabilities for the Claude adapter:** `contextUsage`, `subagents`, `nativeSkills`, `queuedMessages`, `compaction`, `interrupt` and `budgetCap` are all `true`.

## Not verified / caveats

- Behaviour was checked from docs and types only. Nothing was run against a live session (M1 spike work).
- `maxTokens` vs `rawMaxTokens` in `getContextUsage()`: the d.ts has both, but the docs describe only `raw_max_tokens`, and only for the related `SDKContextUsage` payload.
- The `'now'` and `origin: human` behaviour needs Claude Code ≥ 2.1.286. The SDK bundles 2.1.289, so this is fine unless a user points the SDK at an older CLI.
- The SDK releases very often (0.3.x, almost daily). Pin the version in `agent-claude-sdk` and recheck this table when upgrading.
